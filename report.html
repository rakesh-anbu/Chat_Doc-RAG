1. Executive Summary

This project delivers a complete, enterprise-grade Retrieval-Augmented Generation (RAG) system engineered for high-precision, grounded document question answering. Traditional LLM deployments frequently face critical limitations including hallucinated responses, knowledge cutoff boundaries, and catastrophic context length limitations.

To resolve these constraints at zero infrastructure cost ($0 cloud spend), we designed and deployed a serverless vector architecture combining Pinecone Serverless (cosine distance metric, 768 dimensions) with Google Gemini API models (gemini-embedding-001 and gemini-3.5-flash). The system parses heterogeneous document types (.pdf and .json), constructs semantic chunk vector representations, and executes similarity retrieval with strict guardrailed generation.

3. System Architecture & End-to-End Pipeline

The system follows a decoupled Two-Phase Pipeline consisting of (1) Ingestion/Indexing and (2) Runtime Retrieval/Generation:

[Document Input: .pdf / .json] ──► [Chunking: 500 tokens / 50 overlap] ──► [Gemini 768-dim Embedding]
│
▼
[User Question] ──► [Query Embedding] ──► [Pinecone Cosine Search] ──► [Vector Upsert Index]
│
▼ Top 3 Chunks
[Prompt Isolation Delimiters] ──► [Gemini 3.5 Flash Synthesis] ──► [Strict Grounded Response]

3.1 Chunking & Preprocessing Strategy

Documents are extracted into normalized text streams. For PDFs, pypdf reads text blocks across sequential pages. For JSON, structured entities are parsed and formatted into contextual key-value blocks. Text is then chunked via sliding window tokenization (~500 words with 50-word overlap) to guarantee semantic continuity across boundaries.

5. Postman REST API Technical Specifications

All four core stages of the RAG pipeline were independently validated via direct HTTP REST specifications in Postman.

Request 1: Gemini Vector Embedding Generation

POST https://generativelanguage.googleapis.com/v1beta/models/gemini-embedding-001:embedContent?key={{GEMINI_API_KEY}} Headers: Content-Type: application/json Body: { "model": "models/gemini-embedding-001", "content": { "parts": [{ "text": "Customers can return items within 30 days of purchase." }] }, "outputDimensionality": 768 }

Request 2: Pinecone Vector Record Upsert

POST https://rag-knowledge-base-77s36tj.svc.aped-4627-b74a.pinecone.io/vectors/upsert Headers: Api-Key: {{PINECONE_API_KEY}}, Content-Type: application/json Body: { "vectors": [{ "id": "postman_chunk_001", "values": [-0.016728, -0.001609, 0.014829, ... 768 float values], "metadata": { "source": "sample_knowledge.json", "text": "Customers can return items within 30 days of purchase." } }] }

Request 3: Pinecone Vector Similarity Query

POST https://rag-knowledge-base-77s36tj.svc.aped-4627-b74a.pinecone.io/query Headers: Api-Key: {{PINECONE_API_KEY}}, Content-Type: application/json Body: { "vector": [-0.016728, -0.001609, 0.014829, ... 768 float query vector], "topK": 3, "includeMetadata": true, "includeValues": false }

6. Operations & Production Roadmap

Operational CLI Execution

To ingest new documentation or query the live index from the terminal:

Future Architectural Roadmap

  • Hybrid Search (Dense + Sparse BM25): Integrate lexical keyword search with dense embeddings to improve exact-match retrieval for technical part numbers.
  • Cross-Encoder Re-Ranking: Deploy a lightweight Cohere or BGE re-ranker stage to score the top-20 candidates down to top-3 prior to prompt assembly.
  • Web Interface: Wrap query engine in a responsive Streamlit or Next.js user dashboard.
